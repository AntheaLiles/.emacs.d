# Audit de la configuration — septembre 2026

Audit complet de la configuration Emacs 31.1 et de la chaîne Org → LuaLaTeX,
selon trois axes :

1. **Architecture** : les mécanismes maison qui sont devenus de quasi-paquets ;
2. **Natif d'abord** : ce qu'Emacs 30/31 et Org 9.8 savent faire aujourd'hui,
   paquet par paquet, sans régression ;
3. **Performance LaTeX** : où passe le temps, et ce que Lua (et LuaJIT)
   peuvent ou ne peuvent pas y changer.

> [!NOTE]
> **Mise en œuvre.** Les recommandations validées ont été réalisées dans la
> foulée de cet audit (voir `CHANGELOG.md`, section *Non publié*) : backend
> dérivé nommé `pdfua` (et non `these`), classes `article-ua` / `book-ua`,
> passage à CSL-JSON, paquets remplacés par le natif, correctifs de
> fiabilité. Restent volontairement en place : `marginalia` et `corfu`.
> Les chiffres ci-dessous décrivent l'état **avant** ces changements.

Chaque constat porte sa provenance :

| Marque | Sens |
| --- | --- |

## Synthèse

**LaTeX.** Une compilation complète d'un article de six sections prend
**40 s** avec une bibliographie de 14 Mo, dont **18 s de biber** et
**une passe lualatex inutile** sur quatre **[mesuré]**. Deux réglages sans
effet sur le rendu la ramènent à **16,6 s (−59 %)** **[mesuré]**. Tes
macros LaTeX ne coûtent presque rien : le temps part dans les polices,
biblatex, le nombre de passes et biber. **Réécrire en Lua ne ferait rien
gagner de mesurable, et LuaJIT n'est pas une piste** (ni disponible dans le
TeX Live d'Ubuntu, ni compatible avec le Lua 5.3 dont dépendent luaotfload
et le balisage PDF) **[mesuré + vérifié]**.

**Natif.** Emacs 31 rend plusieurs mécanismes maison partiellement
redondants : `TAB` cycle nativement les blocs hideshow (`hs-cycle-filter`),
le répertoire `user-lisp/` compile et scrute les autoloads sans
`compile-angel`, la mode line sait replier les modes mineurs, et
`completion-preview-mode`, `completions-detailed` et `dabbrev-capf` couvrent
une partie de corfu, marginalia et cape **[vérifié]**. En revanche vertico,
orderless, consult, embark, magit, citar, AUCTeX, pdf-tools et org-noter
n'ont **pas** d'équivalent natif sans régression **[avis]**.

**Fiabilité.** Quatre défauts restent, par gravité :

- **Python et R** : les blocs ne peuvent pas s'exécuter dans Org, les
  langages Babel n'étant pas déclarés **[vérifié]**.
- **Lean 4** : aucun mode n'est installé, malgré la configuration d'Eglot
  **[vérifié]**.
- **Eglot** : il démarre dans tous les buffers de programmation, y compris
  les buffers d'édition de blocs source d'Org **[vérifié]**.
- **Obsolescences masquées** : les avertissements d'obsolescence sont coupés,
  alors que tu développes en Emacs Lisp. C'est ce qui a caché les API
  retirées d'Emacs 31 **[vérifié]**.

**Architecture.** Quatre mécanismes dépassent le statut de réglage :
l'export (≈ 620 lignes), la télémétrie (≈ 780), le vérificateur de
dépendances (≈ 440) et le repliement (≈ 260). Le plus rentable est de faire
de l'export un **backend Org dérivé** : aujourd'hui, ses filtres et sa
classe `article` s'appliquent à **tout** export LaTeX, Beamer compris
**[vérifié]**.

## Méthode

- **Lecture** intégrale de `early-init.el`, `init.el`, `lisp/`, `perf/`,
  `latex/`.
- **Sources de référence** (branche `emacs-31`) : `etc/NEWS` (31),
  `etc/NEWS.30`, `etc/ORG-NEWS` (Org 9.8), `hideshow.el`, `flyspell.el`,
  `ox.el`, `ox-latex.el`, `ob-core.el`, `ob-*.el`, et `citar.el`,
  `engrave-faces-latex.el`, `parsebib.el`.
- **Télémétrie réelle** : les fichiers `perf/*.tsv` de ton archive (session
  du 28/09, 8 min, run `20260928T161024-2633`).
- **Banc d'essai LaTeX** : ton préambule **tel quel**, seules les polices
  étant substituées (Luciole → DejaVu Serif, Iosevka → DejaVu Sans Mono,
  Luciole Math → Latin Modern Math), sur un article synthétique de six
  sections : texte, tableaux `tabularx` avec légendes à items, figures,
  citations par section, notes, `\RMQ`, mathématiques, code en ligne.
  Bibliographies : 60 entrées, et 16 605 entrées / 14 Mo (ta taille réelle).
- **Environnement** : Xeon 2,1 GHz, 4 cœurs ; TeX Live 2023 (Debian),
  LuaHBTeX 1.17 ; Emacs 29.3 pour les mesures côté Emacs. La CI valide
  sous Emacs 31.1.

**Limites.**

- Le balisage PDF/UA « phase-III » de TeX Live 2023 est trop ancien pour ton
  préambule (erreur interne de tagpdf), et le CTAN était inaccessible
  d'ici : **le coût du balisage n'a pas pu être mesuré**. Le script
  [`scripts/bench-latex.sh`](../scripts/bench-latex.sh) le mesure sur ta
  machine.
- Les temps absolus dépendent du processeur ; ce sont les **rapports** qui
  comptent.

## 1. Architecture : les quasi-paquets

Un réglage devient un paquet quand il a un **état**, une **API** (commandes,
options), plusieurs centaines de lignes et des **tests**. Quatre mécanismes
franchissent ce seuil.

| Mécanisme | Lignes | État | API | Tests | Verdict |
| --- | ---: | --- | --- | --- | --- |
| Export Org → PDF (`my-export-config`, `-async`, `-ui`) | ≈ 620 | minuteurs, registres | classe, filtres, 4 mots-clés | 7 ERT | **backend dérivé** |
| Télémétrie (`perf/`) | ≈ 780 | tampons, profileur, minuteurs | 14 `defcustom` | 3 ERT | déjà de qualité paquet ; **interrupteur** |
| Dépendances (`my-deps`) | ≈ 440 | cache BLAKE3, processus | 3 commandes | aucun | **simplifier** |
| Repliement (`my-folding`) | ≈ 260 | mode mineur, keymap | 1 mode, 14 touches | aucun | **réduire au natif** |

### Principe général : `user-lisp/` (Emacs 31)

**[vérifié]** Emacs 31 introduit le répertoire `user-lisp/` : les fichiers
qu'il contient sont compilés, leurs cookies `;;;###autoload` scrutés, et le
répertoire ajouté au `load-path`, récursivement (`user-lisp-auto-scrape`,
`user-lisp-directory`, commande `prepare-user-lisp`). C'est exactement le
mécanisme qui manquait pour traiter `lisp/` comme une collection de
paquets locaux.

**[avis]** Proposition :

- `(setopt user-lisp-directory (expand-file-name "lisp/" user-emacs-directory))`
  (ou renommer `lisp/` en `user-lisp/`) et réactiver `user-lisp-auto-scrape` ;
- poser `;;;###autoload` sur les commandes et les modes (`my/folding-mode`,
  `my/deps-check`, `my/citar-open-pdf-with-noter`…) ;
- remplacer les `(require 'my-…)` d'`init.el` par des `use-package … :ensure nil`
  différés, là où le module n'a pas d'effet au chargement.

`early-init.el` désactive aujourd'hui `user-lisp-auto-scrape` au motif que
`compile-angel` couvre aussi les paquets Elpaca. Or Elpaca compile déjà ses
paquets à la construction, et la compilation native JIT les convertit en
`.eln` **[vérifié]**. `compile-angel` ne couvre donc plus que `lisp/`, ce
que `user-lisp/` fait nativement. Le coût du balayage au démarrage (dates
de modification) est **[à mesurer]**, avec la télémétrie avant et après.

### 1.1 L'export Org → LaTeX

C'est le mécanisme le plus riche : classe PDF/UA-2, pipeline latexmk,
quatre mots-clés de flottant (`#+DESC:`, `#+NOTE:`, `#+SOURCE:`,
`#+ALT_TEXT:`), remarques `[rmq:…]`, blocs `TABLE`, conversion drawio,
titres `:ignore:`, code en ligne, repli verbatim, processus asynchrone et
affichage du PDF.

**Problème [vérifié].** Tout est posé **globalement** :

- les filtres vont dans `org-export-before-parsing-functions` et
  `org-export-filter-*-functions`, et s'appliquent donc à **tout** export,
  les réécritures LaTeX à tout backend dérivé de `latex`, **Beamer compris** ;
- la classe `article` d'Org est **remplacée** (`add-to-list 'org-latex-classes`
  sur une clé existante) : un document qui voudrait l'`article` standard ne
  le peut plus ;
- `org-latex-pdf-process` est global, ses options valent pour tous les
  documents.

**Proposition [avis] : un backend dérivé.**

```elisp
(org-export-define-derived-backend 'these 'latex
  :menu-entry '(?t "Export PDF/UA (these)"
                   ((?t "En PDF" my/these-export-to-pdf)
                    (?o "En PDF et ouvrir" …)))
  :options-alist '((:latex-class "LATEX_CLASS" nil "these" t))
  :filters-alist '((:filter-code . my/org-latex-inline-code)
                   (:filter-inline-src-block . my/org-latex-inline-code)))
```

- une classe **`these`** (ou `article-ua`) plutôt que l'écrasement
  d'`article` ;
- les filtres de pré-analyse restent dans
  `org-export-before-parsing-functions`, mais testent
  `(org-export-derived-backend-p backend 'these)` ;
- Beamer et l'export LaTeX standard redeviennent intacts ;
- le processus asynchrone charge le même module : une seule définition.

Coût : une touche de plus dans le menu d'export, et `#+LATEX_CLASS:` à revoir
dans les documents existants. Les 7 tests ERT actuels se transposent.

**`my-export-ui` [vérifié].** L'avis surveille la fin de l'export par un
minuteur toutes les 2 s qui inspecte le buffer `*Org Export Process*`. Or
`org-export-to-file` appelle `org-export-add-to-stack` au moment exact où
un export asynchrone **réussit**, avec le chemin du fichier produit (le PDF,
la compilation ayant lieu dans le processus enfant). Au lancement et en cas
d'échec, la même fonction reçoit le processus. Un conseil `:after` sur
cette fonction distingue donc les trois cas et remplacerait l'interrogation
périodique : plus de minuteur, plus de fenêtre de 60 s pour décider du
succès. Autre défaut : avec
`latexmk -f`, un PDF produit malgré des erreurs passe pour un succès
(§ [5.4](#54-leviers-classés)).

### 1.2 La télémétrie (`perf/`)

Déjà de qualité paquet : documentation du jeu de données, invariant
d'intégrité testé, mesure de son propre surcoût (`overhead.tsv`). Dans ta
session réelle, le collecteur coûte en moyenne **1,75 ms par opération
périodique** (57 opérations, maximum 10 ms) **[mesuré]**, et
`my/perf--snapshot-processes` représente ~2,5 % des échantillons CPU.

**[avis]** Deux ajustements :

- un **interrupteur** (`my/perf-enabled`, lu dans `early-init.el`) : le
  profileur natif tourne en permanence à 10 ms d'échantillonnage. C'est
  légitime pendant une campagne de mesure, pas en usage courant ;
- la bibliothèque **`timeout`** (nouvelle dans Emacs 31, *throttle/debounce*)
  **[vérifié]** conviendrait aux instantanés, plutôt que des minuteurs fixes.

### 1.3 Le vérificateur de dépendances (`my-deps`)

430 lignes : hachage BLAKE3 du dépôt pour décider s'il faut revérifier,
processus Emacs en arrière-plan, rapport persistant. Il est **désactivé**
dans `init.el`.

**[avis] Simplifier.** La vérification elle-même (`executable-find`,
`kpsewhich` par paquet, `fc-list`) est rapide et ne se lance que sur
demande : le cache et le processus asynchrone sont du poids mort. Une
commande `M-x my/deps-check` synchrone, sans cache, d'environ 150 lignes
suffit. On peut aussi ne garder que la liste, sous forme de tableau dans le
README.

### 1.4 Le repliement

`my-folding` reconstruit `TAB` à la Org : cycle sur les titres (outline),
bascule sur les blocs (hideshow), `S-TAB` global, keymap `C-c z`, réglages
par mode (Emacs Lisp, LaTeX, Markdown, commentaires).

**[vérifié] Ce qu'Emacs 31 fait désormais seul :**

- `outline-minor-mode-cycle` : `TAB`/`S-TAB` sur les titres (depuis 28) ;
- **`hs-cycle` et `hs-cycle-filter`** : `TAB` cycle les blocs hideshow ;
- `hs-show-indicators` (frange ou marge), `hs-display-lines-hidden`,
  `hs-toggle-all`, `hs-indentation-mode` ;
- le mode Emacs Lisp définit déjà `outline-regexp` pour `;;;` et `(` en
  colonne 0, soit exactement ce que fait `my/outline-setup-elisp` ;
- les modes tree-sitter prennent désormais en charge `hs-minor-mode` et
  `outline-minor-mode`.

**[vérifié] Ce qui va casser :** `hs-special-modes-alist`, utilisée pour
LaTeX et EBNF, est **obsolète** dans Emacs 31. Il faut désormais poser
`hs-block-start-regexp`, `hs-c-start-regexp`, etc. en variables locales du
buffer.

**Proposition [avis] :** réduire le module à ~60 lignes :

- activer outline et hideshow ;
- `hs-cycle-filter`, `hs-show-indicators` ;
- les variables `hs-*` locales pour LaTeX ;
- l'`outline-regexp` LaTeX et Markdown.

Garder `my/fold-tab-dwim` seulement si la priorité titre > bloc > indentation
diffère du comportement natif dans tes usages. **Régression possible** sur
la sémantique exacte de `TAB` : à essayer une journée avant d'adopter.

## 3. Fiabilité : défauts restants

Constats **non corrigés** à ce jour, par gravité.

| Gravité | Constat | Détail | Correction |
| --- | --- | --- | --- |
| **Haute** | Blocs Python/R/shell inexécutables | `org-babel-load-languages` ne reçoit que `calc` et `mermaid`. Org 9.8 ne charge **pas** `ob-LANG` à la demande : `org-babel-execute-src-block` échoue sur « No org-babel-execute function for python! », et les `org-babel-execute:*` ne sont pas autochargés **[vérifié]** | ajouter `(python . t) (R . t) (shell . t)` ; ESS pour les sessions R |
| **Haute** | Lean 4 non installé | `eglot-server-programs` et `org-src-lang-modes` visent `lean-ts-mode`, mais **aucun paquet ne le fournit** **[vérifié]**. `lean --server` convient à un fichier isolé ; pour un projet Lake (Mathlib), le serveur est `lake serve` | installer un mode Lean 4 et aligner Eglot sur `lake serve` ; vérifier si le mode choisi dépend de `lsp-mode` |
| Moyenne | Eglot partout | `prog-mode-hook` → `eglot-ensure` hors Lisp : tentative de démarrage dans chaque buffer de programmation, y compris **les buffers d'édition de blocs Org** (`C-c '`, sans fichier) et les modes sans serveur installé **[vérifié]** | accrocher Eglot aux seuls modes visés (Lean, Python…) et exclure `org-src-mode` |

### 4.2 Hypothèses sur l'ouverture de `main.org` **[à mesurer]**

1,7 s sans calcul Emacs désigne des processus externes ou des entrées-sorties.
Par ordre de probabilité :

1. **hunspell** : `flyspell-mode` (hook de `text-mode`) lance hunspell, qui
   charge les dictionnaires fr_FR **et** en_US avant de répondre. Coût payé
   à la première ouverture seulement ;
2. **git** : `vc-refresh-state` et `diff-hl` lancent des processus git ;
3. **images** : `org-startup-with-inline-images` lit les images à
   l'ouverture ; coûteux si le wiki est sur `/mnt/c` ;
4. **citar** : les chemins `/mnt/c/…/Zotero/storage` sont testés par
   `citar-has-files` via 9P, lent sous WSL.

Protocole : ouvrir le même fichier trois fois en neutralisant un suspect à
chaque fois (`flyspell-mode`, `diff-hl-mode`, les images), avec la
télémétrie active, puis comparer les lignes d'`events.tsv`.

### 4.3 L'export **[à mesurer]**

74 s de temps réel pour 0,27 s de CPU correspond bien à une compilation
LaTeX **synchrone**, compatible avec les ~40 s mesurées ici sans balisage
(§ 5). Vérifie que tu lances l'export en asynchrone (`C-a` dans le menu,
ou `org-export-in-background`). Côté Emacs, l'export lui-même est
négligeable : **0,16 s** pour 40 blocs et 40 morceaux de code en ligne
colorés par engrave-faces, 0,07 s en verbatim. Le démarrage du processus
asynchrone prend ~0,3 s **[mesuré]**.

### 5.2 Pourquoi quatre passes **[mesuré]**

1. la première passe écrit `.aux` et `.bcf` ;
2. **biber** ;
3. la deuxième passe intègre les citations, la table des matières change ;
4. la troisième règle les références (`lastpage`, `\checkoddpage`) ;
5. **la quatrième ne sert à rien** : latexmk relance parce que `.run.xml` a
   changé, or seuls les indicateurs `active="1"`→`"0"` des requêtes de
   biblatex ont bougé. Ce n'est pas le contenu.

Correctif, validé sans référence non résolue :

```perl
# latex/latexmkrc
$hash_calc_ignore_pattern{'xml'} = '^\s*<(?:internal|external) package="biblatex"';
```

La vraie demande de relance de biblatex passe par son message dans le
`.log`, que latexmk lit par ailleurs : on ne masque rien.

### 5.3 Lua et LuaJIT : verdict

**Réécrire en Lua pour gagner du temps : non [mesuré].** Tes macros coûtent
≈ 0,02 s par passe. Les postes lourds (polices, biblatex, format, balisage,
nombre de passes, biber) ne sont pas du code que tu écris. Aucune boucle,
aucun traitement de texte ni aucun calcul en macros ne justifie un passage
en Lua.

**LuaJIT : non [vérifié].**

- **Disponibilité** : le TeX Live d'Ubuntu ne fournit pas `luajittex`
  (absent de ce conteneur). Avec le TeX Live officiel, il existe, mais comme
  moteur marginal pour LaTeX.
- **Compatibilité** : LuaJIT implémente **Lua 5.1**, LuaTeX **Lua 5.3**. Le
  code Lua de luaotfload et du balisage PDF (tagpdf, luamml pour le MathML
  de PDF/UA-2) vise LuaTeX. Le moteur par défaut de `lualatex` est
  LuaHBTeX : il met en forme le texte avec HarfBuzz, ce que LuaJITTeX ne
  permet pas.
- **Gain théorique** : le JIT n'accélère que le code **Lua** qui tourne en
  boucle. Or le temps d'une passe est surtout du travail TeX (expansion,
  mise en page) et le chargement des polices, déjà mis en cache par
  luaotfload.

**Où Lua aurait du sens, pour d'autres raisons que la vitesse [avis] :**
une logique pénible à écrire en macros. Rien dans le préambule actuel
n'est dans ce cas. `lua-mode` est désormais intégré à Emacs 31 si le
besoin apparaît.

### 5.4 Leviers classés

| # | Levier | Gain | Coût, risque |
| --- | --- | --- | --- |
| 1 | **`.bib` réduite** aux entrées citées (et à leurs `crossref`) | biber 17,9 s → 0,8 s ; compilation 35 s → **16,6 s** **[mesuré]** | voir ci-dessous |
| 2 | **Règle `run.xml`** (§ 5.2) | −1 passe : 21,6 → 16,2 s (petite `.bib`), 40,6 → 35,2 s (14 Mo) **[mesuré]** | nul |
| 3 | **Profil brouillon** : `\DocumentMetadata` sans `testphase`, sans microtype | **[à mesurer]** : le balisage phase-III traite chaque paragraphe et chaque formule (MathML) | deux classes, ou une option de document |
| 4 | **Export du sous-arbre** (`C-c C-e C-s`) pour relire une section | proportionnel à la taille du document | natif Org, aucun |
| 5 | **`lua-ul` conditionnel** | −0,3 à 0,4 s par passe sans code en ligne **[mesuré]** | un filtre de sortie finale |
| 6 | **Retirer `-shell-escape`** | ~0 ; sécurité | faible |
| 7 | **Retirer `-f`** | erreurs visibles | faible |
| 8 | **Cache luaotfload chaud** (`luaotfload-tool -u` après installation de polices) | évite une reconstruction du cache | aucun |

**Obtenir la `.bib` réduite, trois voies [avis] :**

- **Zotero / Better BibTeX** : export automatique d'une collection par
  projet. Aucun code ; il faut tenir la collection à jour.
- **biber lui-même** : `biber --output-format=bibtex --output-resolve doc`
  écrit les seules entrées citées ; c'est ce qu'utilise le script de mesure.
  À relancer quand de nouvelles clés apparaissent.
- **Emacs, au moment de l'export** : relever les clés citées
  (`org-cite-list-keys`, qui prend le canal d'export `info`, donc depuis un
  filtre du backend), copier les entrées brutes depuis la grande `.bib`
  (recherche par clé, `crossref` inclus), écrire `document-refs.bib` et y
  pointer `\addbibresource`. Automatique, sans perte, ~50 lignes dans le
  backend dérivé.

**Alternative radicale : la route CSL [avis].** `org-cite` avec le
processeur `csl` pour LaTeX formate les citations dans Emacs (citeproc-el) :
**plus de biber, une passe de moins**. Mais tu perds les bibliographies par
section (`\newrefsection`) et le style `iso-numeric` de biblatex. Utile
comme **profil brouillon**, pas pour la version finale.

### 5.5 Mesurer chez toi

```sh
# Dans Emacs : C-c C-e l l sur un vrai document, puis
scripts/bench-latex.sh ~/wiki/…/document.tex
```

Le script compile, dans un répertoire temporaire, les variantes `actuel`,
`runxml`, `sansbalis` et `sousbib`, puis une retouche du texte. Il affiche
le temps et le nombre de passes de chacune. C'est la seule façon d'obtenir
le **coût réel du balisage PDF/UA** avec ton TeX Live et tes polices.
